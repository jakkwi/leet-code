# Docs style

The repo is read by hiring reviewers.
- Plain English prose, short sentences. Facts in two-column (or small) tables.
- No emoji, no decorative badges (real CI badges only), relative links inside the repo.
- Never use long dashes (em dash, en dash): commas, colons, parentheses or a plain hyphen.
- Honesty over polish: never claim something the code does not do.
- Problem README: Problem, Intuition, Approaches (table: variant, time, space, idea), Edge cases, Pitfalls. Complexity uses n, m and says what they are.
- PROGRESS.md: one row per problem, variants with time / space, date as YYYY-MM-DD.
